# Folio Rebuild: Minimal Modern Design References

Date: 2026-06-14

Direction: minimal, modern, fast, native-feeling, and media-first. Avoid decorative dashboards, heavy gradients, oversized marketing layouts, and novelty UI. Prioritize calm surfaces, excellent browsing density, keyboard-first workflows, native macOS behaviors, and reliable handling of very large local libraries.

## Reference Principles

1. Native macOS structure should be the baseline: real sidebar hierarchy, toolbar commands, inspector panels, sheets, menus, keyboard shortcuts, drag-and-drop, Quick Look-style previews, and responsive window resizing.
2. The app should feel local-first and immediate. Media grids, metadata, search, tagging, and preview interactions need to feel faster than a web shell.
3. The visual system should be restrained: neutral surfaces, one accent color, clear focus rings, compact controls, no decorative cards, no one-note purple/blue gradient styling.
4. Browsing should carry the product. The primary screen should be a usable library/workspace, not a landing page.
5. AI features, if used, should appear as search, suggestions, clustering, and batch actions rather than a chatbot-centered interface.

## Patterns Worth Stealing

1. Finder + Adobe Bridge: folder-native browsing with optional library intelligence layered on top.
2. Photos + Final Cut Pro: fast visual skimming, timeline/filmstrip concepts, and immersive previews.
3. Raycast + Linear: command-first navigation, saved filters, batch actions, and no-lag keyboard workflows.
4. Eagle + Mylio: tags, smart folders, dedupe, visual search, and media-first organization.
5. Preview + Quick Look: instant viewing with almost no chrome.
6. Figma + Sketch: right-side inspector only when an object or media item is selected.
7. Things + Reeder: restrained typography, generous but efficient spacing, and calm long-session UI.

## Patterns To Avoid

1. Generic SaaS dashboards with charts that do not help manage media.
2. Decorative glassmorphism, gradient blobs, and one-note purple/blue palettes.
3. Card-heavy layouts for everything. Cards should be reserved for repeated media items or contained panels.
4. Chatbot-first UX. AI should accelerate finding, grouping, deduping, and editing.
5. Import-only workflows that make users feel their filesystem is being trapped.
6. Electron-style sluggishness, oversized controls, and web-app spacing inside a desktop shell.
7. Hidden power features that cannot be reached from menus, keyboard shortcuts, or command search.

## Recommended Rebuild Stack

### Recommendation

Use a native Swift/SwiftUI macOS frontend with a Rust backend exposed through a small local service or FFI boundary.

This is a better fit than a Tauri web frontend if the goal is a fast, polished Mac-first media app. The UI should be native because the main complaint is speed and UX quality. Rust should stay where it has clear leverage: scanning, hashing, metadata extraction, thumbnails, search indexing, duplicate detection, image/video analysis, and any AI/ML pipeline that benefits from predictable performance.

### Proposed Stack

1. Frontend: Swift + SwiftUI with AppKit bridges where needed.
2. Native UI escape hatches: AppKit for collection-view performance, advanced drag/drop, custom inspectors, menu commands, and Quick Look integration.
3. Backend core: Rust workspace for library indexing, metadata parsing, thumbnail orchestration, dedupe, search, and long-running jobs.
4. Swift/Rust bridge: UniFFI for typed APIs where possible; C ABI only for narrow hot paths if needed.
5. Storage: SQLite with WAL mode for the local catalog; consider `rusqlite` or `sqlx` in Rust.
6. Search: Tantivy or SQLite FTS5 for local text/metadata search; add vector search later only if useful.
7. Media metadata: Rust crates plus platform fallbacks; preserve sidecar strategy for unsupported formats.
8. Thumbnails/cache: content-addressed cache keyed by file inode/path/fingerprint plus modification time.
9. Background jobs: Rust task queue with progress events to Swift.
10. Packaging: Xcode project for the macOS app, Rust build integrated through a script phase.
11. Updates: Sparkle for macOS app updates if shipping outside the App Store.
12. Testing: Rust unit/integration tests for core library behavior; Swift UI tests for key workflows; snapshot tests for major panes.

### Architecture Shape

```text
Folio.app
  SwiftUI/AppKit shell
  - Library window
  - Media grid/list/timeline
  - Preview and inspector
  - Native commands/menus/shortcuts
  - Settings and onboarding

Rust core
  - Scanner
  - Metadata extractor
  - Thumbnail manager
  - Search index
  - Duplicate detector
  - Job/event system
  - SQLite catalog

Bridge
  - Typed commands
  - Progress streams
  - Cancellation
  - Error mapping
```

### Why This Stack

1. Swift gives us native macOS polish, system behaviors, lower UI overhead, and better access to platform conventions.
2. Rust keeps the performance-critical, testable, portable core separate from UI concerns.
3. The boundary forces discipline: Swift owns interaction; Rust owns data and processing.
4. The app can still become cross-platform later by reusing the Rust core with a different frontend, but the first product should solve the Mac experience properly.

### Risks

1. SwiftUI collection performance can be uneven for very large grids; use AppKit `NSCollectionView` if profiling shows issues.
2. Swift/Rust bridging adds build complexity; keep the API surface small.
3. A native rewrite is slower upfront than reshaping the current frontend, but it directly addresses the speed and UX complaints.
4. Avoid prematurely adding AI/vector infrastructure before the scanner, grid, preview, metadata, and search are excellent.

## Initial Product Direction

1. First screen: library workspace with sidebar, media grid, preview/inspector, and command search.
2. Core promise: browse existing folders without trapping files in a proprietary library.
3. Killer workflow: point Folio at folders, index quickly, browse instantly, search naturally, tag/organize without moving files unless requested.
4. Minimal design language: native sidebars, dense media grid, white/graphite surfaces, one accent color, crisp dividers, no decorative background effects.
5. Performance target: opening the app should show recent/indexed content immediately while background indexing continues visibly.
